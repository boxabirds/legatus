## 1. llama.cpp / llama-server
Flags, from the raw master README (tools/server/README.md, fetched 2026-10-07) [D]:
- `-np/--parallel N` slots (default -1 = auto). `-kvu/--kv-unified` single KV buffer shared across sequences (default enabled if slots auto). `--kv-unified-per-slot N` sizes pool n_parallel*N.
- `-sps/--slot-prompt-similarity` default 0.10 (0 disables).
- `--cache-reuse N` (KV shifting chunk reuse, default 0). Request field `cache_prompt` default true.
- `-ctxcp/--ctx-checkpoints N` max checkpoints per slot, default 32 (README links PR #15293).
- `-cram/--cache-ram N` MiB, default 8192, -1 unlimited, 0 off (PR #16391).
- `--cache-idle-slots` default enabled, needs cache-ram: saves idle slots to prompt cache and clears them when unified KV.
- `--slot-save-path` + /slots save/restore endpoints.
Landing dates:
- SWA checkpoints, PR #15293, merged 2025-08-14 (default then 3 per slot) [D].
- Host-memory prompt cache `--cache-ram`, PR #16391, merged 2025-10-09; also raised default checkpoints 3 -> 8 [D].
- PR #19408 "server: improve context checkpoint logic" merged 2026-02-08 (Qwen3-Coder-Next / hybrid) [D via fetch]. Search snippet says it works with --checkpoint-every-n-tokens; that flag was removed by PR #22929 on 2026-05-25 (replaced by `-cms/--checkpoint-min-step`, default 8192 per particula.tech, master as of 2026-07-29) [U: second-hand blog + search snippet].
Slot selection (server-context.cpp, master, via fetch summary) [D, summary-level]: (1) explicit id_slot; (2) longest-common-prefix: pick slot with highest lcp/len(new prompt) above slot_prompt_similarity; (3) otherwise LRU by t_last_used. If a slot is reused with low retention (<~50%), its prompt is saved to the host prompt cache and the best matching cache entry is loaded; cache entries evicted when cache_ram exceeded. If no slot is idle the task goes to the deferred queue (metrics llamacpp:requests_deferred) [I from code summary + Big Iron/metrics snippet; U exact code lines]. Meaning: requests beyond slots QUEUE; the slot taken when one frees is the similarity-best else LRU, which evicts that slot's live state (to host cache if cache-ram allows).
Hybrid / recurrent behaviour:
- Recurrent state cannot be partially trimmed: seq_rm() on a partial range returns false. So a shared prefix can only be reused where a full-state checkpoint exists at that exact position (<= match point). [D: issue #28425 describes seq_rm false; #20225 item 5 "Recurrent memory can't be partially removed"].
- Full re-prefill every turn bugs: #19794 (Qwen3-Coder-Next, commit 3571565, closed not planned/stale), #20225 (Qwen3.5 27B, b8149/b8233/8182, opened 2026-03-08; partial fixes #19747 #19849 #19877 #19924 #20087 did not fully resolve), #21831 (b8769, closed not planned), #22384 (2026-04-26: checkpoint search used SWA pos_min check, never matched for recurrent; min 64 tokens to checkpoint; fix proposed in a fork spiritbuun/buun-llama-cpp#26; Qwen3.6-27B on 3090 turn-2 prefill 11 s/12,146 tok -> 115 ms/31 tok) [D for issues, fix state in upstream U].
- Current state (master ~2026-07-29 per particula.tech): flags -cms 8192, -ctxcp 32, -cram 8192; checkpoint failures are silent (HTTP 200, only visible at -lv 4); one rejected request erased 15 checkpoints (2.19 GiB); checkpoint sizes 63-214 MiB each so 32/slot x slots can exceed the default 8 GiB cache-ram [U second-hand, but numerically specific].
- Open (2026-09-05): #28425 partial-prefix reuse on qwen4exp (Qwen3.8-Flash-Next) without speculative decoding: n_rs_seq is 0, seq_rm false, server doesn't validate it -> crash or leak on second request sharing a prefix; status open [D].
- #25913: /slots save/restore on hybrid models does not persist checkpoints; restore "succeeds" but recomputes everything (14,906-token prefix: restore 0.12 s, then full recompute; build 10068) [D]. So slot save/restore is NOT a migration path for hybrid sessions.
- #22064 discussion: Qwen3-Next-80B Q8_0 on M4 Ultra 128 GB, 3 slots, ctx 393,216, --ctx-checkpoints 128, --checkpoint-every-n-tokens 4096, --slot-prompt-similarity 0.3, ~75 MiB checkpoints (~10 GB); 1.02-1.03 s on hit vs 39-54 s cold (38-53x); state restored from checkpoint reservoir after slot reuse. Single user report [D as reported; flag since removed].
- Dense (Qwen 3.8 27B, all attention): no checkpoint problem; prefix trimming via seq_rm works, slot similarity + cache_prompt give per-slot prefix reuse. Strix/4090 evidence in repo shows warm turns skip prefill [I; repo docs say agent turns reuse cached prompt].
- Chunked GDN prefill kernels unmerged: Vulkan PR #20377, CUDA/ROCm PR #29353 (per repo doc) [D via repo].

## 3. mlx-lm server and MLX-based servers
- Hybrid models use ArraysCache (non-trimmable) so classic trim-based reuse fails. Upstream mlx_lm.server instead saves checkpoints at segment boundaries (end of system prompt / user turn) [D: LocalAI #12451, reading upstream]. A fork's description: checkpoints at end of system segment and end of prompt minus last token; batched path saves a checkpoint at each segment end except last [U, fork ipsupport-llc/mlx-lm PRs #16/#17].
- LocalAI (own mlx backend) measured: hybrid Qwen3.6-35B-A3B ~360 ms TTFT every turn (no reuse) vs mlx_lm.server ~160 ms warm; full-attention Qwen3-30B-A3B ~107 ms [D as reported].
- LRUPromptCache; v0.31.2/0.31.3 construct it without max_bytes (PR #1392 to honour a byte limit) [U snippet].
- Batching in mlx_lm.server: issue #499 closed (user noted batch_generate best for qwen3-next); a 0.32 port exists in third-party py-vllm-mlx [U]. I could not confirm the exact release that shipped server batching.
- Rollback: mlx-lm PR #1821 (RecurrentCache for MTP rollback) still draft as of ~2026-09-20 [D].
- Qwen3.8-Flash-Next is not in mlx-lm; served via mlx-vlm and its non-trimmable ArraysCache/QSAKVCache; olmlx #745: VLM path excludes checkpoint persistence; cold prefill ~65 tok/s on 64 GB box (9k ~134 s) [D as reported].
- LM Studio mlx-engine v1.8.5: disk-backed KV checkpoints at 256-token boundaries for hybrid/SWA (Qwen 3.5/Gemma 4); M3 Max Qwen3.6-27B-4bit: 82% less extra RAM, 2.2x parallel chat throughput [D, vendor blog].
- mlx-serve #547 (2026-09-25): its embedded llama.cpp engine serves concurrent requests one slot at a time; M3 Max stock llama-server 42.2 tok/s aggregate over 5 seqs vs 29.4 single; five 6-turn agent sessions median response 39-47 s, p95 75 s [D as reported].
- MTPLX: scheduler serial, max_active_requests=1 -> strict queue [D repo doc].

## 4. gufo
- --sessions N: each request leases a preallocated executor with independent KV/recurrent state; /slots llama-server-compatible. Admission queue bounded; requests wait for a session. Prompt reuse default on; up to 128 checkpoints per conversation (separate from session count); checkpoint captured before assistant generation; reuse requires an EXACT prefix (opaque snapshot, cannot trim); RAM cache auto (cap 32 GiB / half free RAM); --cache-disk (8 GiB default) LRU. [D: docs/SERVER.md]. Eviction under pressure keeps another conversation's last useful checkpoint over optional copies [D].
- Issues: #248 prompt reuse, #259 cache-disk, #267 retain learned shared-prefix checkpoints in RAM without cache-disk, #275 disk-cache retention [titles via repo doc/search].

## 6. Implications for a cache-affine proxy
- Affinity key must be the conversation (stable id or hash of the first N messages/system prompt), pinned to node AND, where the engine allows, slot (`id_slot` in llama-server).
- On hybrid models a "near" prefix is worthless unless a checkpoint exists at/before the divergence; re-prefill cost is the cliff. Agent compaction rewrites history and always misses.
- Moving a session between nodes forfeits the cache; /slots save/restore does not carry hybrid checkpoints (#25913), so migration = cold prefill (60k tokens: 47 s gufo, ~230 s llama.cpp on Strix).
- Admission control: keep active sessions per node <= slots (or <= gufo --sessions); over-subscription queues, then LRU-evicts a slot into the RAM cache only if cache-ram holds (checkpoints of 63-214 MiB each can overflow 8 GiB default).
- Health signals to poll: /slots (n_ctx, per-slot prompt), /metrics requests_deferred, and per-response timings.cache_n / usage cached_tokens to measure real hit rate; do not trust HTTP 200.
